# 哇鸥 · 去大坝整点饵块

像素风网页小游戏。主角是一只留在昆明滇池没飞回西伯利亚的红嘴鸥,叫**哇鸥**。
设定、内容与玩法方向见 [DESIGN.md](DESIGN.md)。

`npm run dev` 后打开 http://localhost:5173

## 怎么做出来的

这个项目是**人 + AI 协作**完成的,分工大致是「人定方向和取舍,AI 出实现和初稿」。
下面这份记录是给 vibecoding 比赛看的,也是给以后接手的人看的 —— 它说明
哪些决定是有人拍板的,哪些是可以随便改的。

### 人做的

**定方向。** 角色叫哇鸥、形象长什么样(原始形象图由 IP 方提供)、
故事发生在昆明滇池、明信片用哪些地标、食材用哪些云南小吃、
玩法往放置养成靠、小屋是什么样的场景、三个互动分别是什么、
哪个时间段能见到它 —— 这些没有一条是 AI 提的。

**否决和纠偏。** 项目里质量提升最大的几次改动都来自这一侧:

| 人说的 | 改了什么 |
|---|---|
| 「icon 和边框搭配时会越界」 | 挖出 em 尺寸导致非整数倍缩放,整套图标系统重做 |
| 「游戏画面做的太丑」 | 从 canvas 直接画改成低分辨率缓冲 + 整数倍放大的像素管线 |
| 「形象设计有点太丑了,直接改成豆豆眼」 | 角色识别点重定,所有尺寸一起换 |
| 「构图应该是侧视图,而非水平图」 | 待机界面从分层示意图改成有视角的构图 |
| 「小屋的时间应该跟大坝的时间同步」 | 挖出两套时钟并存,统一成一个,并连带修了「睡着还在表演」 |

**验收。** 每一版美术、每一处构图都是看了截图再决定改不改。

### AI 做的

全部代码(约 5000 行 JS)、全部像素美术的生成脚本、架构分层、数值平衡、
文案初稿,以及一部分设定的展开 —— 其中「红嘴鸥每年从西伯利亚飞到滇池越冬,
红嘴红脚就是它的招牌」这个把角色和昆明接起来的钩子是 AI 提的。

也包括几个自己挖出来的 bug:迁移函数引用了会随版本变化的常量、
`tickStalls` 把合盖一夜的时间差按在线全额结算、明信片掉落写死了 7 张
导致后三张永远掉不出来。

## 画面怎么画的

游戏画面**先在 440×310 的低分辨率缓冲上作画,再整块放大 2 倍**贴到 880×620 的 canvas。

这一层不是为了省性能,是画风问题:直接在 880×620 上画,一条 `arc()` 出来的太阳、
一条正弦浪都是带抗锯齿的软边,旁边却是硬边的像素 UI,两边对不上,
配色再准也只会显得脏。低分辨率作画之后,每个像素点都是实打实的 2×2 方块。

跟着来的两条约束:

- **坐标必须是整数。** 玩法本身就跑在 440×310 的虚拟坐标里,不是画的时候才除以 2。
- **画面尺寸必须整数倍。** `.px-stage` 宽度写死 916px 就是为了让 `.px-screen`
  正好是 880×620;差一点点(比如被挤成 844)整块画面按 0.959 倍缩放,
  `image-rendering: pixelated` 下像素立刻一大一小。

### 手机上呢

916px 那条只在**桌面**成立。手机屏放不下,画面会被 CSS 缩到三百多。
量过之后结论没那么糟 —— 关键是设备像素,不是 CSS 像素:

| | CSS 宽 | 设备像素 | 对 880 位图 |
|---|---|---|---|
| iPhone 15(DPR 3) | 354 | 1062 | 1.21× 上采样 |
| Pixel 7(DPR 2.6) | 376 | 978 | 1.11× 上采样 |
| 中端安卓(DPR 2) | 324 | 648 | 0.74× 轻微下采样 |
| 桌面窗口拉到 390 宽(DPR 1) | 354 | 354 | 0.40×,明显 |

**上采样不掉像素**,所以真机上画面是干净的;只有把桌面窗口拉窄才会难看,
而那不是真实的使用场景。所以这里没做特殊处理,窄屏只收了排版
(标题、HUD、内衬),页签摊成一条横着滑。

真正在手机上会**玩不了**的是另一件事,已修:飞行玩法要在画布上按住不放
(右半边按住 = 平飞),而默认情况下浏览器把手指在画面上的移动当成滚页面,
直接发一个 `pointercancel` —— 那一下平飞就断了。
`#flyCanvas` 上的 `touch-action: none` 就是干这个的,别删。

### 今日运势卡片

占卜的结果会画成一张 1080×1440 的竖图(`js/game/card.js`),玩家能存下来发出去。
3:4 是小红书的竖图比例。

一张卡 = **背景 × 版式 × 天光**。目前 4 × 2 × 3 = 24 种组合,
`npm run dev` 之后打开 **`/card-preview.html`** 一页看全。

#### 改文案 → `js/data.js` 的 `FORTUNES`

八条,每条五个字段:

| 字段 | 显示在哪 | 写多长 |
|---|---|---|
| `name` | 卡片正中那行大字 | 「档次 · 两个字」,别超过 8 个字 |
| `text` | 卡片底部带引号那句,哇鸥的口气 | 一句话 |
| `long` | 卡片正文 | 两三行。**要能被没玩过的人读懂** |
| `yi` / `ji` | 宜 / 忌 两个小块 | 6 个字以内,再长会顶到对面那块 |

**签不带任何数值效果**,以后也别加。一个「大凶」真去砍当天的产出,
玩家只会学会「凶了今天就别上线」—— 一个每日一次的仪式,
不该变成开不开游戏的理由。所以宜忌写成建议:指向玩法里本来就有的选择
(今天该屯还是该开摊、要不要多飞两趟),读起来像有用,实际一个数不动。

**改完跑 `npm run font`** —— 新字不在字体子集里就会掉回系统字体。

#### 改图 → `js/game/card.js` 的三张表

```js
CARD_SCENES   背景。一个背景 = 一个 paint(c, P, h) 函数,在 360×h 里画完
CARD_STYLES   版式。文字区从哪开始(top)、什么底色(bg / scrim)、什么字色
CARD_PHASES   天光。day / dusk / night
```

加一个背景就是加一个函数再往 `CARD_SCENES` 里挂一行,预览页会自动多出一列。

三条规矩:

- **背景里不要写死颜色。** 用传进来的那个 `P`(来自 `scene.js` 的 `pal()`),
  它是游戏画面用的同一套色板 —— 写死了天气和时段就跟不上,
  而且卡片和游戏画面迟早会漂成两个色调。
- **文字只用 12 / 24 两个字号。** 字体本体是 12px 设计的,别的字号都在拉伸。
- **在 360×480 上画完再整块放大 3 倍**,不要直接在 1080×1440 上画 ——
  否则文字和像素图会一个软一个硬。

#### 两个容易踩的

- **画完转成 data URL 塞进 `<img>`,不直接摆一块 canvas。** 手机上长按 `<img>`
  才有「保存图片」,长按 canvas 没有 —— 而在国内的浏览器里长按保存比
  `<a download>` 靠谱得多。
- **必须等 `document.fonts.ready`。** canvas 画字是一次性的,字体没到就画,
  会拿系统字体落下去,而且不会像 DOM 那样自己回流重排。

#### 调试

```js
wa.fortune(3, 4)                                  // 把今日签设成第 3 卦、第 4 种花纹
wa.card()                                         // 列出可选的背景 / 版式 / 天光
wa.card({ scene:'city', style:'full', phase:'night' })  // 钉住某个组合
wa.card(null)                                     // 恢复成按当天自动挑
```

默认按「日期 + 签的 id」挑组合:**同一天同一卦永远是同一张**
(玩家反复打开不会看到图变来变去),换一天又不一样。天光跟真实时段走 ——
晚上转的卦画成夜景,这比随机挑更说得通。

### 开场引导

四步(`js/data.js` 的 `TUTORIAL`),让第一次打开的人看懂三条线是一个圈:
觅食囤材料 → 摊子自动吃材料出餐 → 不出去时在坝上表演被投喂补材料。

**每一步靠 `done(state, ui)` 读状态判定,不靠「玩家点了哪个按钮」。**
挂在按钮上的引导,一旦玩家用别的路径达成就会卡在原地等一个不会来的点击。
`advanceTutorial()` 每次重绘跑一遍,所以 `done()` 必须是纯读取。

老档升 v8 时一律标成走完 —— 能升级上来的存档,人早就会玩了。
`wa.tutorial(0)` 可以拨回去再看一遍;`?scene=fresh` 是唯一保留引导的预设档。

### 音效

**全部现场合成,一个音频文件都不带**(`js/audio.js`)。理由和像素画同一条:
美术是几十 KB 的字符网格换来的,再挂两百 KB 的 mp3 就本末倒置了。
芯片音本来就该是振荡器出来的,采样反而不对味。

三件踩过的事写在文件头上,这里只提最要紧的一条:**AudioContext 只能在
用户手势之后建**。页面一加载就 `new` 一个,拿到的是 suspended,之后再怎么
play 都没声 —— 所以是懒建的,第一次真要发声时才建,那时必然已经点过。

静音开关存 localStorage,**不进存档**:它是这台设备上的偏好,不是玩家的进度。
存档码是要复制给别人、换设备用的,把「我这儿静音」一起带过去毫无道理。

`wa.sfx()` 列出全部音名,`wa.sfx('coin')` 试听 —— 改音色时热更新之后直接再敲一次。

### 字体

界面字体是 Fusion Pixel(OFL 开源)。完整包 31345 个码位、588 KB,
游戏实际用到一千四百出头 —— 剩下三万个字形是纯过路费,而且这笔钱是首屏付的。

所以走子集:

```bash
npm run font          # 重新生成 css/fonts/waou-pixel.woff2(588 KB -> 45 KB)
npm run font:check    # 只检查源码里有没有字漏在子集外
```

`npm run build` 会先跑一遍 check。**漏掉的字不会报错,只会无声无息掉回系统字体**,
一句话里几个字忽然变了样 —— 这种事没人会在提交前发现,所以让构建来管。

检查连注释里的字一起收。分不清哪句会渲染、哪句只是注释,与其写个半吊子的
注释剥离器(剥错了就是静默漏字),不如多收几 KB 换一个只会误报、不会漏报的检查。

## 放置玩法

三件事咬成一个闭环:**摊位吃食材,表演产食材,觅食囤食材。**

```
        ┌──── 表演:哇鸥在大坝上演,路人投喂 ────┐
        │      (被动、慢,故意补不满)          ↓
   觅食一趟 ──────────→ 背包 ──────────→ 摊位出餐 ──→ 鸥币 ──→ 升级
   (主动、量大)          ↑                  吃食材          ↑
                        └──────────────────────────────────┘
```

摊位吃不到食材就停着等 —— 这条是关节,它让「出去觅食」和「挂机赚钱」
互相咬住,而不是两件不相干的事。表演补的是「摊位一直吃、食材却只能手动囤」
的缺口,但**故意补不满**:炉子一升、格子一开就跟不上,还是得出去飞。

觅食的产出跟着等级走(`haulPerPickup`),后期一趟带回来的是前期的四倍 ——
不然摊位吃得快了,再一颗一颗捡就跟不上。

表演的节目单由**等级 / 成就 / 明信片**三处解锁,节目越多围观越多、投喂越勤、
给的东西越杂。把「去过的地方多」做成真的有回报,而不只是图鉴上多一个格子。

三条容易踩的坑,都在 `js/game/rules.js` 里写着:

1. **在线和离线走同一个 `produce()`**,只有倍率不同。两条路各写一遍,迟早算出不一样的数。
2. **材料断供时要把计时压回一个周期以内。** 不压的话,材料一补上会「一次性补发」
   几百份 —— 挂机一晚等于白送。
3. **`tickStalls` 里时间差超过一分钟就转交离线结算。** 笔记本合盖、标签页被浏览器
   冻结,页面还开着但下一次 tick 会一口气看到几小时。按在线全额算的话,
   离线上限和折扣全绕过去了:挂着标签页睡一觉比老老实实关页面赚得还多。

调数值时用 `wa.rate()` 看当前产能,`wa.away(3)` 假装离线 3 小时。

## 养成

**季节按真实月份走。** 红嘴鸥每年 11 月到次年 3 月在昆明越冬,这是真事,
不该变成一个游戏内的抽象计时器。代价是夏天会冷清好几个月 —— 这是故意的:
冬天鸥群回来时才有那个「热闹起来了」的落差。

| 季节 | 客流 | 稀有食材 | 招伙计 |
|---|---|---|---|
| 冬(11–3 月) | ×1.4 | ×1.0 | ✅ |
| 春(4–5 月) | ×1.0 | ×1.0 | — |
| 夏(6–8 月) | ×0.8 | **×2.0**(雨季菌子疯长) | — |
| 秋(9–10 月) | ×1.1 | ×1.2 | — |

**伙计鸥**六只,一只管一件事(出餐快 / 卖得贵 / 表演招人 / 觅食多带 /
离线少亏 / 稀有多出),不叠加同类效果 —— 玩家一眼看得出该先招谁。
门槛卡在**好感度**上:得先和哇鸥处熟了,它才肯把亲戚介绍给你。
而且**只有冬天招得到** —— 鸥群不在昆明的时候没人可招,这条比任何
「等级 ≥ N」都自然。

**食材图鉴**记的是**累计见过多少**,花掉了不减 —— 图鉴是见闻不是库存。
所有加食材的路径都走 `rules.js` 的 `gain()`,拿背包反推会越玩越少。

## 小屋

堤岸边的一个草棚,**全游戏唯一的近景** —— 别处都是远远看着哇鸥,只有这里能看清它的脸。
所以棚里除了必要的结构什么都不放,视线全给它。

**全游戏只有一个时钟**(`js/data.js` 的 `hourSlot` / `dayPhase`)——
大坝的天光和小屋开不开门都从那儿读,两边各算一套的话迟早对不上。

| 时段 | 哇鸥在哪 |
|---|---|
| 11:30 – 13:30 | 小屋(醒着) |
| 19:00 – 22:30 | 小屋(醒着) |
| 22:30 – 05:30 | 小屋(睡着,只能看) |
| 其余时间 | 大坝上 —— 摆摊、表演 |

`hourSlot` 管「哇鸥在哪」,`dayPhase` 管「画面什么颜色」,**两者刻意分开**:
它 11:30 回屋,但天不会在 11:30 变暗。

跟着来的两条:

- **哇鸥不在大坝上时,大坝画面里就没有它**,表演也不产食材。
  离线结算会按五分钟一格采样,算出那段时间里有多少是它在大坝上的
  (见 `rules.js` 的 `damMsIn`)—— 睡着的时候还有人投喂就说不通了。
- 大坝画面上有个**草棚,点它就进小屋**。画和点用同一份坐标
  (`scene.js` 的 `SHACK_HIT`),分开写的话挪一次位置就会「看着在这儿、点不到」。

屋里能做三件事:

| | |
|---|---|
| **占卜** | 海鸥一族的老法子:看天气,再看捡来那枚贝壳上的纹。**一共只有八种结果**,一天一次 |
| **海鸥四子棋** | 黑石头白石头,你执白先手。AI 会赢会堵,但不搜索 —— 它是只海鸥,不是引擎,输给玩家是常事 |
| **请它喝一杯** | 每天上线随机拿到普洱茶或咖啡(两样都是云南的),带去给它,加好感度 |

哇鸥在屋里多数时候是窝着的一团,**每隔一阵伸出两条细腿站起来走两步**再窝回去。
腿是画上去的不是精灵图 —— 走路时腿的角度一直在变,做成帧图要画一大堆。

## 分层约定

- **规则层不碰 DOM。** `rules.js` 里所有会改变存档的动作都返回一个「事件」数组,
  由 `ui.js` 决定怎么呈现。这样规则能单独测,也不会像重构前那样在逻辑里直接 `alert()`。
- **改存档只走 `main.js` 的 `mutate()`。** 它负责触发保存和重绘,别的地方不要直接改 state。
- **存储接口是异步的**,即使 localStorage 是同步的。将来换云存储或后端不用改业务代码。

## 数值体检

```bash
node tools/sim.mjs                          # 三种玩家画像各跑 30 天
node tools/sim.mjs --days 60 --who active
node tools/sim.mjs --start 2026-06-01       # 从夏天起跑,专看淡季
node tools/sim.mjs --csv                    # 输出 CSV 拿去画图
```

不开浏览器,把 `rules.js` 按天空跑,打印等级 / 鸥币 / 瓶盖 / 材料 / 成就的曲线,
最后回答几个具体问题:升到 10 级要几天、瓶盖够不够买齐装扮、升级线哪天见底、
哪几样材料是瓶颈、背包哪天溢出存档上限。

**它模拟规则,不模拟飞行。** 一局觅食吃到多少是代入的假设(`RUN` 那张表),
因为飞行需要 canvas 和一双真手。数字是照着 `flight.js` 的生成密度估的 ——
不服就改那张表重跑,这正是它的用处:换个假设看曲线怎么动,
比争论「手感好不好」有用。

改完数值请把结论同步进 `DESIGN.md` 的「数值体检」—— 曲线本身不会自己记得
你为什么这么调。

**改了数值就跑一遍。** 一个放置游戏的问题都在第十天、第三十天那儿,
而没人会为了调数值真玩一个月。当前跑出来的结论记在 `DESIGN.md` 的「数值体检」。

## 调试玩法

每天 5 次觅食、等级靠攒经验、天气 5 分钟随机换一次 —— 这些是给玩家的节奏,
不是给你调玩法的。`npm run dev` 下会在 `window` 上挂一个 `wa`,控制台敲 `wa.help()` 看全部命令。

```js
wa.scene('mid')    // 切到预设存档并重载(原档自动备份)
wa.rate()          // 当前产能:每份间隔 / 每分钟多少钱 / 离线上限
wa.away(3)         // 假装离线 3 小时,一秒内结算并弹吐司
wa.stall(0, 'shao_erkuai')   // 第 0 格摆烧饵块
wa.maxUp()         // 四条升级线拉满,看数值天花板
wa.shows()         // 表演:解锁了哪些节目、多久投喂一次
wa.hour(20)        // 把时钟拨到 20 点 —— 小屋按时段开门,不然得真等到晚上
wa.drink('puer')   // 再发一杯,反复试「请哇鸥喝」
wa.reFortune()     // 清掉今日占卜,好再转一卦
wa.season('winter')// 拨季节 —— 冬天才招得到伙计,不然要等到 11 月
wa.hire('huihui')  // 直接招一只,跳过季节和好感度检查
wa.lv(5)           // 直接跳到 5 级,食谱跟着解锁
wa.tries(99)       // 觅食次数管够
wa.fill()          // 背包装满
wa.weather('rainy')
wa.unlockAll()     // 食谱 / 明信片 / 成就 / 装扮全开
wa.wear('douli')   // 直接戴上某件装扮;wa.wear() 列出全部 id
wa.caps(99)    // 设瓶盖数 —— 装扮只能用瓶盖买
wa.event('roll')   // 随机触发一件大坝事件;wa.event() 列出全部
wa.eventSoon()     // 把事件计时推到临界点,等它自己冒出来
wa.restore()       // 把切场景之前那份存档换回来
```

也可以直接写 URL,调试起点就成了可以收藏、可以分享的链接:

```
/?scene=mid          预设存档
/?seed=42            固定飞行的随机序列
/?tries=99&weather=rainy
/?time=night         待机界面钉住时段(day / dusk / night)
/?hour=20            把游戏时钟拨到 20 点(小屋)
/?season=winter      拨季节(winter / spring / summer / autumn)
/?enter              跳过待机界面直接进游戏
/?tab=wear           进去停在哪一页(dock/hut/bag/cook/postcard/achievement/wear/chat/save)
```

`?enter&tab=` 是给截图和「反复看同一页」用的:手点还好,脚本截图每次都要
先点开始再点页签,多跑两轮就够烦了。`?scene=dressed` 是专门调装扮的预设 ——
瓶盖管够、五件全在手上、已经戴了一身。

**要重复跑同一局,用 `?seed=`。** 飞行的食材和障碍生成走的是注入进去的随机源
(`js/game/rng.js`),同一个种子每次跑出同一串东西 —— 不然「刚才那下是难度问题
还是我运气差」永远说不清。天气轮换、明信片掉落、订单抽取还是 `Math.random`,
那些不影响一局能不能重放。

**要加自己的调试场景,改 `js/dev.js` 顶部的 `SCENES`。**
每一项是一个补丁,盖在全新存档上,没写的字段保持默认,食谱解锁按 level 自动补齐:

```js
SCENES.boss = { level: 7, coins: 5000, items: { shield: 9 } };
```

整个 `dev.js` 由 `import.meta.env.DEV` 包着动态 import,`vite build` 时是常量 false,
连同 `rng.js` 一起被摇掉,生产包里搜不到一个字节。

### 数值在哪改

| 想调 | 改哪 |
|---|---|
| 食谱、订单、明信片、成就、天气系数 | `js/data.js` |
| 食材的**名字和图标** | `js/data.js` 的 `FOODS`(改这两样不用迁移) |
| 食材的**键** | `js/data.js` + `js/state.js` 的 `FOOD_KEYS`,并且 `SAVE_VERSION` +1 补迁移 |
| 开局背包、每日次数 `DAILY_TRIES`、存档字段 | `js/state.js` |
| 经验曲线、明信片掉率、订单刷新 | `js/game/rules.js` |
| 摊位出餐间隔 `SERVE_MS`、升级四条线的系数和价格 | `js/data.js` 的 `UPGRADES` |
| 摊位格子的解锁等级 | `js/data.js` 的 `STALL_SLOTS` |
| 天气对客流的影响、离线的一分钟门槛 | `js/game/rules.js` 顶部常量 |
| 表演的节目单和解锁条件、投喂间隔 `SHOW_MS` | `js/data.js` 的 `SHOWS` |
| 觅食产出随等级的斜率 | `js/game/rules.js` 的 `haulPerPickup` |
| 待机界面的构图、三个时段的配色 | `js/game/title.js` 顶部常量 |
| 小屋开门的时段、天光的分界 | `js/data.js` 的 `hourSlot()` / `dayPhase()` |
| 草棚在大坝上的位置和点击范围 | `js/game/scene.js` 的 `SHACK_HIT` |
| 傍晚/夜晚的偏色和压暗程度 | `js/game/scene.js` 的 `PHASE` |
| 占卜的八种结果、天气偏移 | `js/data.js` 的 `FORTUNES` / `WEATHER_SHIFT` |
| 每日饮品、好感度加多少 | `js/data.js` 的 `DRINKS` |
| 四子棋 AI 的强弱 | `js/game/connect4.js` 的 `aiMove` |
| 季节的月份分界和系数 | `js/data.js` 的 `SEASONS` / `seasonOf` |
| 伙计鸥的效果、价格、好感门槛 | `js/data.js` 的 `CREW` |
| 飞行速度、生成间隔、判定半径、连击加成 | `js/game/flight.js` 顶部的常量和 `_update()` |
| 画面构图(海平线、甲板高度、陈设位置) | `js/game/scene.js`、`background.js` 顶部的常量 |

`data.js` 大部分是纯静态目录,不进存档 —— 增删条目不用写迁移。
**例外是 `FOODS` 和 `ITEMS` 的键**,它们是 `backpack` / `items` 的字段名,直接进存档。

写迁移有一条铁律:**迁移函数只能依赖写死的、当时的字段表,不能引用 `FOOD_KEYS`
这类会随版本变化的常量。** 否则升级到下一版时,更早的那级迁移会拿着新常量去读老档,
数据在第一步就被清零,后面再也捞不回来 —— v1→v2 那次就踩了,见 `state.js` 里
`migrations[0]` 的注释。
